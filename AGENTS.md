# AGENTS.md — служебные заметки для агентов

Проект: PWA «Дневник питания». Vanilla HTML/CSS/JS, IndexedDB, service worker. Без сборки, без npm-зависимостей. Файлы приложения лежат в **корне репозитория** (`index.html`, `app.js`, `style.css`, `sw.js`, `manifest.webmanifest`, иконки) — так требует GitHub Pages и так был устроен проект изначально; не перемещать в подпапку. Локальная проверка: `node serve.js` → http://127.0.0.1:8123/.

Язык общения с пользователем — русский. Пользователь с git руками не работает.

Личных данных в репозитории нет и быть не должно. История: репозиторий был публичным → 2026-11-24 переведён в приватный → в тот же день возвращён в публичный ради Pages. ## Секреты и приватность

- Перед каждым коммитом работает pre-commit хук `.git/hooks/pre-commit`: запускает `gitleaks git --staged --redact .` и отменяет коммит при находках. Обход — только осознанно и с объяснением пользователю: `git commit --no-verify`.
- Хук живёт в `.git/` и **не версионируется**: при переклонировании репозитория его нужно установить заново (текст хука — в истории этого файла либо пересоздать по описанию выше).
- `.gitignore`: `log.txt`, `.env`, `.env.*`, `*.key`, `*.pem`, `node_modules/`, служебные файлы Windows/редакторов.
- `log.txt` — личный дневник питания пользователя. **Принципиально не коммитить и не отправлять на GitHub** (решение пользователя от 2026-11-24; файл тогда же удалён с диска, но может появиться снова — запись в `.gitignore` его подстраховывает).
- Репозиторий публичный: перед коммитом любых новых файлов (документы, выгрузки, заметки) проверять, что в них нет личных данных — теперь это важнее, чем раньше.
- 2026-11-24 полная проверка gitleaks: рабочие файлы и вся история на GitHub чисты, секретов нет.
- Правило проекта: пароли, ключи и токены не хранить в файлах проекта. Если gitleaks находит реальный секрет — не коммитить, объяснить пользователю, какой ключ отозвать.

## Данные пользователя

- Записи дневника (приёмы пищи, вес, заметки) хранятся только на устройствах пользователя в IndexedDB браузера. В git и на GitHub они не попадают никогда.
- В приложении есть экспорт/восстановление: «Сохранить копию (JSON)» / «Восстановить из копии» (app.js, раздел export/import). Перед любыми операциями, затрагивающими размещение приложения, предлагать пользователю сделать JSON-копию.
